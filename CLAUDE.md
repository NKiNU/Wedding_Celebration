# CLAUDE.md — Wedding Memories (guest web app)

Mobile web app where wedding guests share **photos, albums, videos and wishes** on one shared wall, and can find the couple's **DuitNow QR** for a money gift. Guests join with a unique name only (no password). Built mainly for **Safari (iOS)** and **Chrome (Android)**.

Design references:
- Interactive prototype + wireframe: Claude canvas "Wedding Memories App" (hi-fi monochrome phone, wireframe phone).
- Original mockups: Canva design "Golden Mango Twist" (pages 1–5 are the app; page 6 is an unrelated reference).

**Development plan and progress: `docs/PLAN.md`.** Read it before starting work. Decisions are recorded in `docs/adr/` (R2 for media, one event per deployment, upload intents). Coverage floor is 80%.

When behaviour in this file and the prototype disagree, this file wins. Ask before changing any rule marked **[rule]**.

## Stack

- **Next.js** (App Router, TypeScript strict, React Server Components where possible)
- **Supabase**: Postgres (data), Realtime (live wall)
- **Cloudflare R2**: all media (photos, videos, posters, thumbnails, QR); see `docs/adr/001-r2-for-media.md`
- **Tailwind CSS v4** driven by CSS variables (see Theming); tokens are mapped with `@theme inline` in `theme.css`, so there is no `tailwind.config.ts`
- **zod** for every input that crosses the network, and for env vars
- Deploy: a VPS (Node, `npm run build` + `npm start` behind an HTTPS reverse proxy) + Supabase (hosted); see `docs/PLAN.md` "Deploy target is a VPS"

## Identity: name only, no password **[rule]**

- A guest enters a name. Trim, collapse spaces, 2–24 characters.
- Names are **unique per event, case-insensitive** (`Ali` = `ali`). Enforce with a unique index on `(event_id, lower(name))`, not only in the UI.
- If the name is taken → return `409` with 2 suggestions (`"Ali 2"`, `"Ali & family"`, skipping ones also taken). **Never** log someone in as an existing name just because they typed it.
- On success the server creates a random 32-byte **device token** per guest and stores only `sha256(token + DEVICE_TOKEN_PEPPER)`.
- Cookies (`httpOnly; Secure; SameSite=Lax`, 1 year):
  - `wm_tokens`: the raw tokens of every name created on this phone (max 5).
  - `wm_active`: which of those is the current identity.
- `GET /api/session` returns `{ active, known: [{ guestId, name }] }` so the welcome screen can show "Continue as Ali" chips. No localStorage needed.
- `POST /api/session { guestId }` makes one of this phone's guests active ("Continue as"). The server accepts it only if `wm_tokens` holds that guest's token. Typing a name this phone already owns takes the same path; any other taken name is a `409`.
- Every non-GET route handler goes through `handle(req, ...)`, which rejects cross-site requests (`Sec-Fetch-Site` / `Origin`) with `403`. Route handlers get no CSRF protection from Next.
- **Ownership is by token, never by name.** Delete is allowed only when the active token's hash matches the post's guest.
- "Switch name" only clears `wm_active`; the guest, their posts and their token stay, so "Continue as Ali" still works on this phone. Another phone typing "Ali" gets the "name taken" path.
- iOS Safari can clear site data after 7 days of no use (ITP). That is acceptable for a one-day event; do not build account recovery.

## Data model (Postgres)

```sql
create table events (
  id uuid primary key default gen_random_uuid(),
  slug text unique not null,
  groom_name text not null,
  bride_name text not null,
  header_message text default 'Raikan memori anda bersama',
  qr_path text,                 -- storage path of admin-uploaded DuitNow QR
  qr_account_name text,         -- shown under the QR so guests can verify
  qr_bank text,
  uploads_open boolean not null default true,
  created_at timestamptz default now()
);

create table guests (
  id uuid primary key default gen_random_uuid(),
  event_id uuid not null references events(id) on delete cascade,
  name text not null,
  token_hash text not null unique,
  created_at timestamptz default now()
);
create unique index guests_event_name_ci on guests (event_id, lower(name));

create type post_type as enum ('photo', 'album', 'video', 'wish');

create table posts (
  id uuid primary key default gen_random_uuid(),
  event_id uuid not null references events(id) on delete cascade,
  guest_id uuid not null references guests(id) on delete cascade,
  type post_type not null,
  caption text check (char_length(caption) <= 120),
  wish_text text check (char_length(wish_text) between 3 and 300),
  hidden boolean not null default false,   -- admin moderation
  created_at timestamptz default now(),
  check ((type = 'wish') = (wish_text is not null))
);
create index posts_wall on posts (event_id, created_at desc) where not hidden;

create table post_media (
  id uuid primary key default gen_random_uuid(),
  post_id uuid not null references posts(id) on delete cascade,
  position smallint not null,              -- order inside an album
  kind text not null check (kind in ('image', 'video')),
  path text not null,                      -- storage path
  poster_path text,                        -- video poster frame
  width int, height int, duration_s numeric
);
```

- `type` is derived on the server: 1 image → `photo`, 2–10 images → `album`, 1 video → `video`. Never trust the client's type.
- RLS: enable on all tables. Anonymous clients may only `select` from `posts` (not hidden) + `post_media` + `events`. The guest list is not readable by anon (`public_guests` is service-role only since Phase 6: PDPA, and the app never needed it). **All writes go through route handlers using the service role after verifying the device token.** Never expose `token_hash`.
- Deleting a post also deletes its storage objects (do it in the route handler, then delete the row).

## Media rules

- Photos: 1–10 per post. Resize on the client before upload (long edge 2048 px, JPEG quality ~0.82) and also make a 600 px thumbnail for the grid. iOS gives HEIC from the camera roll in some cases: convert via canvas before upload.
- Video: 1 per post, **≤ 80 MB and ≤ 30 s** (keeps the event inside the R2 free tier; the event's posted media is capped at 9 GB, `MAX_EVENT_MB`). Read duration on the client from `<video>` metadata and reject early with a friendly message. Capture a poster frame (seek to 0.5 s, draw to canvas) for the grid.
- Uploads go **directly to R2 with presigned PUT URLs** issued by `/api/uploads` (an upload intent, see `docs/adr/003-upload-intents.md`); then call `/api/posts` with the `postId`. Show real progress per file. If a post creation fails, clean up the orphaned files.
- R2 keys: `events/{eventId}/{postId}/{position}.{ext}`, plus `{position}_thumb.jpg` and `{position}_poster.jpg`; QR at `events/{eventId}/admin/qr-{uuid}.{ext}`. Reads go through the public custom domain with unguessable UUID keys.
- `post_media` also stores `thumb_path`, `bytes` and `mime`.
- Rate limit per device: 30 posts / hour, 200 MB / hour. Per address: 300 new names / 10 min (a venue shares one Wi-Fi address). The event's posted media is capped at 9 GB. No limit on reading the wall, on purpose (every phone refetches it on each new post). All in `limits.ts`.

## Screens and behaviour (match the prototype)

1. **Welcome** — monogram, couple names, "Your name" input, Start. Shows "Continue as X" chips for names created on this phone. Inline error + suggestion chips when a name is taken.
2. **Wall (home)**
   - Header: monogram, name chip (opens Me drawer), "The wedding of", couple names, header message, count of memories, **Latest wishes ticker** (rotates every 4 s, tap opens that wish).
   - Sticky filter pills: All · Photos (includes albums) · Videos · Wishes, each with a count.
   - 2-column card grid. Card types: photo, **album (stacked photos + count badge)**, video (play icon + duration), wish (text card, 5-line clamp). Card footer: author, relative time, "You" badge on own posts.
   - Empty state per filter with a call to action.
   - Bottom-right **+ FAB** opens a labelled action menu: Photos, Video, Wish, DuitNow QR. FAB turns into ×.
   - New posts appear live via Supabase Realtime (insert/update/delete on `posts`, plus the `post_hidden` broadcast on `wall:<eventId>` for moderation; see `docs/PLAN.md` Data model). Paginate with infinite scroll, 24 per page.
3. **Bottom drawers** (one `BottomSheet` component: drag handle, title, close button, scrim tap closes, focus trapped, Escape closes)
   - Photos: picker (multiple), preview grid with remove, hint "will post as album" when >1, optional caption, Post button shows count, progress while uploading.
   - Video: picker (single), file name/size, validation error, optional caption, progress.
   - Wish: quick-start chips, textarea, counter 0/300, Send.
   - DuitNow QR: admin's QR image, account holder name + bank, **Download QR**, 3 steps (save → banking app → DuitNow QR → scan from gallery → check name). Not a post; nothing is stored.
   - Wish view: full wish, author, time; "Delete my wish" for the owner.
   - Me: name, "remembered on this phone", list of own posts with delete, Switch name.
4. **Post viewer** `/p/[id]` (full screen, dark): back, author + time, delete (owner only). Photo: fit to screen. Album: swipe + prev/next buttons, "2 / 5" counter, thumbnail strip. Video: native `<video controls playsinline>` with poster. Caption below.
5. **Delete** always goes through a confirm dialog ("Delete this album? Guests will not see it anymore."). Toast after success.
6. **Admin** `/admin` (passcode from `ADMIN_PASSCODE`, stored in an httpOnly cookie): edit couple names + header message, upload/replace DuitNow QR + account name + bank, open/close uploads, hide/unhide/delete any post, download all media as a zip.

## Theming **[rule]**

The client may change the palette and fonts later. Keep the look 100 % token-driven:

- All colours, fonts, radii and shadows live in `src/styles/theme.css` as CSS variables and are mapped with `@theme inline` in the same file (`bg-paper`, `text-ink`, …). ESLint enforces this in `src/components`. **No hex values or font names inside components.**
- Default theme (pure monochrome, from the Canva mockups):

```css
:root {
  --ink: #141414;        /* text, primary buttons, active pill, wish cards */
  --paper: #F4F3EF;      /* page background */
  --card: #FFFFFF;       /* cards, inactive pills */
  --soft: #C9D3DC;       /* inputs, secondary buttons, "You" badge */
  --muted: #62625E;      /* secondary text (passes 4.5:1 on paper) */
  --line: #DCDAD3;       /* borders, dividers */
  --sheet: #FBFAF7;      /* drawers, dialogs */
  --viewer: #0E0E0E;     /* full-screen viewer */
  --font-body: 'Poppins', system-ui, sans-serif;
  --font-script: 'Pinyon Script', cursive;            /* monogram + couple names only */
  --font-serif: 'Cormorant Garamond', Georgia, serif; /* wish text, italic */
  --radius-card: 18px;
  --radius-media: 12px;
  --feed-pattern: radial-gradient(rgba(20,20,20,.2) 1px, transparent 1.35px) 0 0 / 6px 6px; /* halftone */
}
```

- Decorations (lace frame, floral line art, halftone) are separate components behind a `decor` flag so a theme can drop them.
- Keep a `[data-theme="wireframe"]` theme (white, grey lines, system font, no decor) for client reviews.

## Safari + Chrome mobile checklist

- Inputs and textareas use `font-size: 16px` or larger (stops iOS zoom on focus).
- Use `100dvh` and `env(safe-area-inset-*)` for full-height screens, the FAB and drawers. Add `viewport-fit=cover`.
- `<video playsinline controls>`; never autoplay with sound.
- File inputs: `accept="image/*"` (with `multiple`) and `accept="video/*"`; do not set `capture` so guests can pick from gallery.
- **Download QR**: prefer `navigator.share({ files: [qrFile] })` when `navigator.canShare({ files })` is true (iOS shows "Save Image" to Photos). Fallback: `<a download>`; on iOS that saves to Files, so also show "or long-press the QR and tap Save to Photos".
- Touch targets ≥ 44 × 44 px. Respect `prefers-reduced-motion` for drawer/FAB animations.
- Test on a real iPhone (Safari) and Android (Chrome) before every release, including slow 3G upload.

## Conventions

- TypeScript strict; no `any`. Validate every request body with zod in `lib/validation.ts`.
- Server-only code imports `server-only`. The service role key must never reach a client bundle.
- Relative times ("5 min ago") with `Intl.RelativeTimeFormat`; UI copy in English, couple's header message may be Malay.
- Accessible by default: real `<button>`/`<label>`, `aria-label` on icon buttons, focus returns to the trigger when a drawer closes.
- Small, focused components; one drawer per file.
- Write tests for: name normalisation + uniqueness, token ownership on delete, post type derivation, media limits.

## Do not

- Do not add passwords, email, phone number or social login.
- Do not let the client choose `post.type`, `guest_id` or the author name on a post.
- Do not store raw device tokens.
- Do not hardcode colours or fonts in components.
- Do not store anything about money gifts; the app only displays the QR.
- Do not collect personal data beyond the display name (keep PDPA exposure minimal); add a short privacy note on the welcome screen.
